# Ember Studio 0.5.0 preview (build de6494fe), Windows x64

No release has been published yet. This note describes the build the documentation was checked against, so that it can be read before anything is published.

This is a preview of Ember Studio. Studio is the window you look at; ember-lab is the program that runs training and the model. Read what works and what does not before you install.

## What works

- Studio opens as one native Windows window, with no console window, and shows nine tabs: Agent, Train, Library, Models, Evals, Weights, Research, Console and Timeline. The window opens on Agent.
- The pages that read your folders (data packs, models, evaluation results, weights, press receipts) draw them when you point Studio at the folders with a flag. Each page tells you which flag it wants. See [command line](../command-line.md).
- The Agent tab is a chat with a model that can read and edit files in one folder under approvals. The model is the lab's resident model, or any model you name in an opencode-style provider config file (`model`: `provider/model`, over plain `http`). Long sessions are summarised by the model and continue; the state line shows the prompt-read time and the first-token time as two numbers; a turn the lab cuts says why. See the [Agent guide](../tabs/agent.md).
- The Train tab has a mode strip: pretraining is shown dormant, finetuning (full, LoRA, QLoRA) shows its memory need against the card. See [Train](../tabs/train.md).
- The Library tab draws your data packs as a reading room of bookcases in 3D, or as a size-sorted list. The Research tab draws donor and recipient networks in 3D. The Weights tab can draw a tower of the live model's layers from the file header.
- You can draw any tab to a picture without opening a window, and drive Studio from a script, with `monitor --render-png`, `--act`, `--act-set` and `ui-tree`, without touching the mouse or taking the keyboard focus. See [command line](../command-line.md).
- The lab's folders, tools and drive are settings (`ember-lab.toml` or environment variables), not paths built into the program; `ember-lab paths` prints them. See [lab](../lab.md).
- Every page says in words what it cannot find or reach.

## What does not work

- Anything that needs ember-lab needs you to run one: starting, watching or stopping a training job, the Agent tab's resident model, and live job state. Without a lab Studio says "lab not answering", and a tab the lab cannot serve is drawn disabled with the reason. No download of the lab has been published.
- There is no Linux or macOS build. See [platforms](../platforms.md).
- The program is not signed, so Windows SmartScreen may warn you.
- Several controls were not exercised while the documentation was written; the list is in [known limits](../known-limits.md). In particular, starting and stopping an hour was not run.

## Check your download

The release page lists a checksum file. It holds the SHA-256 of the zip. In PowerShell, in the folder you downloaded to:

```
(Get-FileHash .\<the zip you downloaded> -Algorithm SHA256).Hash.ToLower()
Get-Content .\<the checksum file>
```

The first line you see must match the zip's line in the checksum file, character for character. If it does not, do not run the file.

## How it was built

From commit `de6494fe` of the private source repository, in release mode, with the build command of that repository, which maps the build machine's folder names out of the program and scans the finished program for any that remain. A separate scan of this build's program file for the folder names of the machine it was built on found none. The program is a Windows GUI program, which is why no console window opens with it. The Rust test results for this commit are not part of this note.
