# Ember Studio 0.5.0 preview (build edb7d3ad), Windows x64

This is a preview of Ember Studio only. Studio is the window you look at; ember-lab is the program that actually runs training and the model, and it is not part of this release yet. Read what works and what does not before you install.

## What works

- Studio opens as one native Windows window, with no console window, and shows the nine tabs: Agent, Train, Library, Models, Evals, Weights, Research, Console and Timeline.
- The pages that read your folders (data packs, models, evaluation results, weights, press receipts) draw them when you point Studio at the folders with a flag. Each page tells you which flag it wants. See [command line](../command-line.md).
- The Library tab draws your data packs as books on shelves in a 3D room, or as a size-sorted list. The Research tab draws donor and recipient networks in 3D, side by side in two panes. See the [Library](../tabs/library.md) and [Research](../tabs/research.md) guides.
- The Train tab draws the job a running lab reports as three cards, and the [Hour view](../tabs/hour-view.md) lists every check an hour has to pass before it can start, each as OK or NO with the lab's own words.
- The Agent tab shows the states of the resident model in words, including what it does when a job needs the GPU card (yielding, asleep until the card is back, card busy). See the [Agent guide](../tabs/agent.md).
- You can draw any tab to a picture without opening a window, and drive Studio from a script, with `monitor --render-png`, `--act` and `ui-tree`, without touching the mouse or taking the keyboard focus. See [command line](../command-line.md).
- Every page says in words what it cannot find or reach. Nothing fails silently.

## What does not work

- Anything that needs ember-lab does not work, because ember-lab is not released: starting, watching or stopping a training job, the Agent tab's model, and live job state. Studio says "lab not answering" for these. The lab release is pending until the lab's folders can be set by you instead of being fixed to the author's machine. No date is promised.
- There is no Linux or macOS download. A Linux build compiles and draws in a test environment, but its tests do not build yet, so it is not released. There is no macOS build. See [platforms](../platforms.md).
- The program is not signed, so Windows SmartScreen may warn you.
- Several controls were not exercised while the documentation was written; the list is in [known limits](../known-limits.md). In particular, starting and stopping an hour was not run.

## Check your download

The release page lists a file called `SHA256SUMS`. It holds the SHA-256 of the zip. In PowerShell, in the folder you downloaded to:

```
(Get-FileHash .\ember-studio-0.5.0-edb7d3ad-windows-x64.zip -Algorithm SHA256).Hash.ToLower()
Get-Content .\SHA256SUMS
```

The first line you see must match the zip's line in `SHA256SUMS`, character for character. If it does not, do not run the file. The zip also carries its own `SHA256SUMS` for the program file inside it.

## What is inside the zip

- `ember-studio-edb7d3ad.exe`: Ember Studio. The name carries the short code of the source commit it was built from.
- `SHA256SUMS`: the SHA-256 of that program file.
- `RELEASE-NOTES.md`: this text.

## How it was built

From commit `edb7d3ad` of the private source repository, on Windows 11, in release mode. The build script refuses to start if the program's source folder has any uncommitted change or untracked file, and checks again after the build and refuses if the build left one; this build passed both checks. The program is a Windows GUI program: the executable's subsystem field says so, which is why no console window opens with it. The Rust test results for this commit are not part of this release.
