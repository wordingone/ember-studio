# Ember Studio 0.5.0 (build 185b8abd), Windows x64

This is the first build published from this repository. It is a build of the program as it stands, not a feature release: read [Known limits](../known-limits.md) before you rely on any page.

## What is in the zip

- `ember-studio-185b8abd.exe`: Ember Studio, a native Windows GUI program (no console window opens with it).
- `SHA256SUMS`: the SHA-256 of the exe, for a check after you unzip.
- `RELEASE-NOTES.md`: this file.

The zip itself is `ember-studio-0.5.0-185b8abd-windows-x64.zip`; its hash is in the `SHA256SUMS` file published beside it on the release page.

(Get-FileHash .\ember-studio-0.5.0-185b8abd-windows-x64.zip -Algorithm SHA256).Hash.ToLower()

## How it was built

- From commit `185b8abd` of the private source repository, in a freshly made worktree. The build script refuses a dirty tree and found it clean.
- On Windows 11 with Rust 1.92, `cargo build --release --locked --offline`, four compile jobs at below-normal priority, one build at a time.
- Source and toolchain paths are remapped out of the binary.
- The PE subsystem is WINDOWS_GUI (checked with the repository's own subsystem checker).
- Smoke test after the build: `ui-tree` on the new exe printed the same control names as the exe the documentation was written against.
- The Rust test suite was not run for this build: several of its tests host a pseudoconsole and open windows, and a real job was using the machine.

## Not in this release

- The lab daemon (`ember-lab`). It is built from the same commit, but it still contains fixed paths to the author's machine, so it is not released. Studio shows what it reads from files and says when the lab is absent. See [How Studio talks to ember-lab](../lab.md).
- Linux and macOS builds: see [platforms](../platforms.md).
- Code signing: the exe is not signed. Windows SmartScreen may warn; verify the hash first.
